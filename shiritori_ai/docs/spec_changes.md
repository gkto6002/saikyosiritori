# 仕様から改善した点

## 1. 大規模対戦の打ち切り条件を分離

- 変更前: 最大手数到達をタイムアウト処理に含める案があった。
- 変更後: `turn_timeout`、`max_moves_reached`、`match_timeout` を分けて記録する。
- 理由: AIの1手あたり思考時間超過と、試合全体の打ち切りは意味が異なるため。
- 期待される効果: 勝率、計算時間、打ち切り理由をレポートで混同せずに分析できる。

## 2. 最大手数を大きめにし、試合全体タイムアウトを追加

- 変更前: `max_moves=500` を推奨値としていた。
- 変更後: デフォルトは `max_moves=min(dict_size, 3000)` とし、別に `max_match_time_sec=120` を設ける。
- 理由: D10000以上では500手だと短すぎる可能性がある一方、無制限では実験が終わらない。
- 期待される効果: 大規模辞書でも長めの対戦を許しつつ、実験全体が停止しにくくなる。

## 3. ファイル分割は中間構成に調整

- 変更前: `core/`、`agents/`、`simulation/`、`experiments/` など細かく分ける案。
- 変更後: `dataset.py`、`game.py`、`exact_solver.py`、`agents.py`、`match.py`、`experiments_exact.py`、`experiments_approx.py`、`visualize.py`、`human_cli.py` に整理。
- 理由: 細かすぎる分割は管理コストが上がるため。実験単位の入口を独立させることを優先した。
- 期待される効果: 特定の手順だけ実行しやすく、パラメータ変更時に触る範囲も把握しやすい。

## 4. JMdict抽出は優先度付きseedサンプリングに変更

- 変更前: 優先語を単に前方へ並べる案。
- 変更後: `ke_pri` と `re_pri` から優先度を算出し、優先度の高い語を中心に候補プールを作り、固定random_seedでD語を抽出する。
- 理由: JMdict XML上の並び順に依存せず、一般語を中心にしつつseed差を作るため。
- 期待される効果: 小規模完全解析で、特定の単語集合に依存しすぎない複数seed実験ができる。

## 5. 手順履歴はJSONLにも保存

- 変更前: CSV出力中心。
- 変更後: 集計しやすいCSVに加え、手順履歴は `match_logs.jsonl` に保存する。
- 理由: 手順履歴はネストした構造で、CSVだけでは扱いにくい。
- 期待される効果: 集計用データと詳細ログを分けられる。
