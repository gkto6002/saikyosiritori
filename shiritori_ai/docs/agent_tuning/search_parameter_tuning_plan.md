# 探索パラメータ・適応深度検証計画

## 目的

AlphaBeta、PVS、BeamNegamaxを個別に改善し、固定深度の基本設定と適応深度の効果を混同せずに評価する。HybridAgentや新しい探索方式は実装しない。

## 既存実装の利用

- AI対AIは`RuntimeDictionary`から作る`EdgeDictionary`と`AIEdgeState`だけを使う。
- 固定局面の復元には`benchmarks/existing_agents_benchmark.py`の形式を使う。
- AlphaBetaのルートalpha共有、PVSのnull window、Beamの深度別幅、既存評価関数は変更しない。
- D5000比較の基準設定（AlphaBeta D5/B8、PVS D5/B8、Beam D5/8-6-4-2、1手1秒、固定深度）を必ず残す。
- 既存の`results/existing_agent_improvement`と`results/agent_comparison`は上書きしない。

## 実験順序

1. D5000の実対局ログからseed 0・1を調整用、seed 2を最終確認用として固定局面を抽出する。
2. `adaptive_depth=false`で深度5・6を測る。
3. 同じ設定の深度6が安全な場合だけ深度7を測る。
4. タイムアウト率、p95、ルート完了率、手の一致率から各手法の有力設定を選ぶ。
5. 有力設定を固定、保守的、標準、積極的の各適応規則で比較する。
6. seed 0・1だけで最終候補を選び、seed 2は選定後の確認だけに使う。
7. 基準設定、改善固定、改善適応を必要な組合せだけD5000で対戦させる。
8. CSV、JSON、値ラベル付きPNG、Markdownレポートを生成する。

## 固定深度の候補

- AlphaBeta/PVS: depth 5, 6, 7 × branch limit 8, 12, 16
- Beam:
  - 8-6-4-2
  - 12-8-4-2
  - 12-8-6-4
  - 16-12-8-4
  - 各depth 5, 6, 7

Beam幅配列より深いplyでは既存仕様どおり最後の幅を繰り返す。この仕様をテストとレポートへ残す。

## 深度7の事前選別

対応する深度6について、調整用固定局面で次をすべて満たす場合だけ深度7を実行する。

- タイムアウト率20%以下
- p95が制限時間の90%以下
- 平均ルート探索完了率50%以上

除外した深度7も設定一覧へ残し、対応する深度6の測定値と除外理由を保存する。

## 適応規則

- `depth`は初期深度、`max_depth`は上昇可能な安全上限として分離する。
- ハード制限時間は探索停止専用とし、深度調整には通常目標時間を使う。
- 保守的: 初期+1まで、通常目標はハード制限の25%、80%以上で低下、40%以下が3手で上昇
- 標準: 初期+2まで、通常目標はハード制限の40%、90%以上で低下、50%以下が3手で上昇
- 積極的: 初期+2まで、通常目標はハード制限の60%、95%以上で低下、60%以下が2手で上昇

通常CLIでは最大深度増分の既定値を0、通常目標時間の既定値をハード制限時間とし、
既存挙動を維持する。最小深度、最大深度増分、通常目標時間、変化幅、
タイムアウト時に下げるかも外部指定可能にする。

固定深度の探索方法と評価関数は変更しない。以前の互換性のある固定深度runは
`--reuse-fixed-from`で新しい適応深度実験へコピーし、不要な再測定を避ける。

## 出力

`results/search_parameter_tuning/<run-hash>/`以下へ、manifest、固定局面、固定深度結果、適応比較、対局結果、集計、図、最終レポートを保存する。同一設定は再開時に再実行しない。

## 大規模辞書への移行

D5000は候補設定の探索に使用する。以降は、複数seedのRuntimeDictionaryが揃う
D50000を標準の対局辞書とする。`--selection-from`でD5000の固定設定を移植し、
D50000上では移植した3設定だけを再測定してから適応プロファイルを選び直す。
対局上限は既定で3000手、1対局600秒とし、いずれもCLIから変更可能にする。

D50000で上位となった方式は、D100000、D150000、D170000の順に確認する。
これらは現状seed 0だけなので、複数seed比較を行う場合は同条件の辞書を追加生成する。

D50000の対局は、まずseed 0で次の12対局だけをパイロット実行する。

- 各AIの改善固定対改善適応を先後入替えで6対局
- 改善適応3手法の先後入替え総当たり6対局

`--match-limit`で一度に実行する新規対局数を区切り、所要時間と結果を確認してから
続行する。パイロットで不利な設定を除外し、上位設定だけをseed 1・2へ展開する。

## 判断上の簡略化

- 固定局面の同一設定は決定的なので原則1回測定し、局面間分布を使う。
- 全設定の大規模総当たりは行わない。
- AlphaBetaを参照手として使うが、真の最善手とは呼ばない。
- Beamの各内部plyでAlphaBetaの主変化を追跡する機能は追加せず、ルート参照手の順位・保持率と実際の選択手一致率を主要指標にする。
