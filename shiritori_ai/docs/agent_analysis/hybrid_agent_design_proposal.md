# HybridAgent設計提案

## 前提

今回は設計提案だけで、HybridAgentは実装していない。

分析上、AlphaBetaとPVSは固定同一局面90/90で同じ手を選び、最終成績も35/48で同一だった。実対局D5ではAlphaBetaの平均0.1329秒・1,143 nodesに対し、PVSは0.1425秒・1,295 nodesだった。

BeamはAlphaBeta/PVSへそれぞれ2勝12敗で、勝利時52.1手、敗北時119.4手だった。参照手top 8保持率は実対局95.1%だが、実手一致率は48.7%である。

## 採用提案

最も有望なのは、次の「AlphaBeta主系・Beam時間バックアップ型」である。

```text
通常:
    AlphaBeta D5/B8

候補数が8以下:
    branch limitを解除したAlphaBeta

danger / near_death:
    AlphaBetaを維持し、候補を削らない

soft deadlineまでにAlphaBetaが一手も完了できない:
    Beam D5/8-6-4-2ではなく、
    事前に完了済みの軽量候補または浅いBeam結果をfallbackとして利用
```

### 根拠

- AlphaBetaはPVSと同じ判断で最終設定では速い。
- Beamをnormalの主系にする案は、normal top 8保持率93.9%と直接対決2勝12敗から支持されない。
- Beamの価値は強さより、固定幅による処理量予測と完走保証にある。
- near-deathでは参照手保持・一致が高く候補自体も少ないため、近似へ切り替えるよりAlphaBetaの候補制限を解除する方が安全。

### 想定欠点

- AlphaBetaが時間内に一候補も完了しない局面ではfallback品質が不安定。
- 同一手中の複数方式実行は重複計算になる。
- 現在は禁止範囲だった反復深化や置換表なしでは、探索結果の再利用が難しい。

### 実装難易度

中。既存AIを合成するだけでなく、deadline、完了ルート数、状態復元、どの結果を正式採用するかを統一する必要がある。

### 検証方法

1. 固定局面でAlphaBeta単独との選択一致率を確認する。
2. 時間予算0.05、0.1、0.25、1.0秒でtimeoutと完了候補数を測る。
3. normal候補17以上、caution、danger、near-deathを層別する。
4. D1000〜D20000、seed 0〜2、先後入替で対局する。
5. Beam fallbackが使われた局面だけを別集計する。
6. 参照手保持率ではなく、最終勝敗と状態復元を主要合否にする。

## 次点案

Beamを残すなら、root候補17以上のnormal局面だけ幅16-10-6-3へ広げる案が次点である。実対局参照手はtop 16で100%保持された。ただし参照手が候補内でもBeam実手一致率は低いため、これだけでAlphaBeta並みになる保証はない。

PVSをAlphaBetaの代わりに使う理由は現時点ではない。置換表、反復深化、終盤完全解析を後で導入した際に、PVSの窓制御が有利になるかを改めて測るべきである。
